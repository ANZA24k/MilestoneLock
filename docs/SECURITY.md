# Security and trust boundaries

- Commitments bind sponsor, contractor, milestone ID, policy and the full specification. Acceptance checks the exact commitment. There is no specification edit method.
- Evidence requires HTTPS, exact raw.githubusercontent.com, a full commit hash and a .txt file; credentials, ports, query strings, path traversal and mutable branches are rejected. The source must return HTTP 200. GitHub is trusted to serve the committed raw bytes; SHA-256 and exact size authenticate them independently.
- Inputs, documents, criteria counts and model output are bounded. JSON strings reject duplicate fields. Documents are untrusted data, never executable commands or prompt authority. A specification defines the task but cannot override the fixed reviewer safety policy.
- Every validator runs its own retrieval and semantic assessment. It compares criterion IDs/findings, evidence-rule finding, final outcome and reason; verifies every proposed excerpt against the authenticated document; and independently asks whether every proposed finding is grounded. Enum/shape checks alone are never sufficient.
- Uncertainty cannot authorize settlement. Transient source/model failures revert and preserve the revision for retry. Persistent hash/length mismatch is a recorded INCONCLUSIVE result. A failed consensus transaction does not append a successful decision.
- Only the contractor can accept or submit, and only the sponsor can cancel an unaccepted offer. Different nonzero parties are required. Any account can review. Successful approval cannot be revised or approved twice. Evidence hashes cannot be reused on the same milestone.
- Up to three completed revisions preserve old documents, reports, reviewers and decision hashes. No infinite retry history or global candidate capacity can be filled by another user. Public submission and permissionless review can still incur network cost and spam; this is a development pilot.
- The website uses textContent for contract content, validates externally linked evidence URLs and never renders evidence HTML. File selection only hashes local bytes; files are not uploaded by the website. Receipt integrity does not prove scientific or real-world truth.
- No value is accepted, held or sent by the contract. Reference amounts do not reserve money or create an on-chain payment. No production security audit is claimed.
- Studionet may reset. Model errors, disagreement and source downtime can delay review. Export important receipts, but verify them against finalized chain state and the exact deployed source.
